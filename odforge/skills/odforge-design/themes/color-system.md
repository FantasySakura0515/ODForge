# 配色方法論：怎麼配出好看又讀得清的簡報色

給 LLM 讀的配色深指南。`SKILL.md §③` 講 palette 契約與對比門檻，這份講**如何配色**。
自訂 `design.palette` 前先讀這份；沿用內建主題（academic/minimal/dark/teal/forest/navy/
violet）時，這份是理解它們為什麼那樣配的背景。

## 一、把 5-token palette 當成 60-30-10

主流簡報配色的骨架是 **60-30-10 法則**：60% 主導色、30% 次要色、10% 強調色。這讓視線
有層次、不被單一顏色淹沒。ODForge 的五個 token 本來就是這個結構——照著用就對：

| 比例 | 角色 | 對應 token | 怎麼用 |
| --- | --- | --- | --- |
| **60%** | 主導／底 | `bg` | 頁面大面積背景。中性、安靜，不搶內容 |
| **30%** | 結構／文字 | `surface` + `text` + `muted` | 色塊底、內文、次要文字，撐出資訊層次 |
| **10%** | 強調 | `accent` | **全簡報唯一的彩色**，只點在一個關鍵字／標題底線／一條 highlight 長條 |

`accent` 的力量來自**省著用**。用超過 10%，它就不再是強調，整頁會亂、會吵。一頁最多讓
一件事發光。

## 二、自訂 palette 的配色配方

要客製 `design.palette` 時，照這個順序配，六格一次到位：

1. **先定一個底（bg）**：選暖／中性色，別用刺眼純白或純黑。淺底用暖 off-white 或 cream
   （`#F6F2E9` 這類）比 `#FFFFFF` 耐看；深底用深靛／午夜紫／墨綠這種帶色的深，別用死黑。
2. **surface = bg 位移一階**：淺底就比 bg 深一點點，深底就比 bg 亮一點點。只是用來分色塊，
   不要跳太多。
3. **text = 近黑或近白**：淺底配近黑（帶一點底色的深灰，如深藍灰 `#1B2A2C`），深底配近白
   冷灰。要 text/bg ≥ 4.5。
4. **muted = text 調淡到「剛好過 3:1」**：次要文字要看得到但不搶主文。調淡後務必確認
   muted/bg ≥ 3.0，這是暗底最容易踩的雷——淺文字掉到中灰就糊。
5. **accent = 單一飽和色相**：整份只挑**一個**強調色相。要 accent/bg ≥ 3.0。
6. **title_color**：通常等於 text；只有暗底想讓標題更亮時才另設。

## 三、趨勢方向：calm, clear, credible

2025–2026 的主流簡報配色在往「冷靜、清楚、可信」走，遠離吵雜。落成守則：

- **暖中性底勝純白**：cream／warm off-white 比 `#FFFFFF` 更耐看、更 editorial。
- **單一自然色強調**：teal（2026 年度色）、forest green、navy 這類自然色最百搭可信；
  一份簡報只用一個強調色相。
- **不要 neon、不要第二個強調色相**：多個亮色相會讓簡報顯得業餘、失焦。
- **不要純黑配純白硬對比**：對比要夠（過門檻），但用近黑／近白＋帶色的底，比死黑白柔和。
- **一份 3–5 色收斂**：五個 token 剛好；別再往裡塞更多顏色。

## 四、無障礙：不只過門檻，還要色盲讀得懂

對比門檻（`SKILL.md §③` 會擋）是底線，但圖表還要多守幾條——約 8% 男性有紅綠色盲：

- **強調靠亮度、不只靠色相**：highlight 長條和其他長條，除了色相不同，**明暗也要拉開**，
  這樣色盲也分得出哪條被點亮。ODForge 的 chart 用 `accent` 點亮、其餘用中性色，本身就是
  靠亮度區隔——維持這個習慣，別把所有長條塗成同亮度的不同色相。
- **絕不只靠顏色傳達意義**：該標的重點，除了上色也要有文字／位置／highlight 索引佐證。
- **避免紅配綠**：紅綠、綠棕、藍紫是最常被色盲混淆的組合。要對比就走藍配橘、teal 配洋紅
  這種色盲安全的方向。
- **相鄰資料序 ≥ 3:1**：多條長條並排時，相鄰兩條之間也要有 3:1 對比，不是只跟背景比。

配完後，回到 `SKILL.md §③` 的對比自檢把 text/bg、accent/bg、muted/bg 三道算一遍再送。
