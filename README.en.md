# ODForge

Generate native ODF documents from a single sentence: presentations (`.odp`), text documents (`.odt`) and spreadsheets (`.ods`).

English | [繁體中文](README.md)

![python](https://img.shields.io/badge/python-3.11%2B-blue) ![license](https://img.shields.io/badge/license-MIT-green) ![format](https://img.shields.io/badge/output-native%20ODF-orange)

```bash
odforge new "A lecture deck on binary trees for a data structures course" -o tree.odp --language en
```

![A slide generated by ODForge](odforge/demo/tree.png)

The LLM only writes content, as structured JSON (the Document IR) that is validated
against a schema. The rendering engine writes the XML, and the result then goes
through validation gates. The model never touches the file format, so a model mistake
cannot corrupt the file structure, and every piece of text on a slide stays editable
instead of being baked into an image.

## Features

- **Three document types**: presentations (19 slide layouts, including charts, processes,
  timelines, metrics, diagrams, tables and image layouts), text documents (heading levels,
  table of contents, tables, quotes) and spreadsheets (multiple sheets, native formulas).
- **Two-stage presentations**: an outline comes first (art direction plus a skeleton for each
  slide); slides are filled in after you confirm it, and you can stop in between to edit.
- **Design system**: 13 color themes and several composition styles. CJK font sizing and line
  breaking are handled, and presentations embed their CJK fonts so they look the same on
  machines without those fonts.
- **Reuse existing templates**: give it an `.otp` / `.odp` / `.ott` / `.odt` and it extracts the
  colors and fonts for the new deck.
- **Assets**: insert your own images and a cover logo; an external image-generation service can be plugged in.
- **Four quality gates**: zip structure, XML, an actual LibreOffice conversion, and a vision
  model that reviews each slide and repairs what it finds.
- **Overflow check**: lays the file out with LibreOffice and finds text that spills out of its
  frame, past the right margin or off the page — for ODForge's own output and for any
  `.odp` / `.odt` / `.docx` you are handed.
- **Web editor**: `odforge edit deck.odp` lets you drag, resize and retype directly in the browser,
  add, remove and reorder slides, with alignment guides and spacing readouts; every step saves
  back to the `.odp`. No LibreOffice window involved.
- **Live preview**: your own AI agent (Claude Code, Codex) writes the content; `odforge preview`
  shows the laid-out result and any overflow in the browser as it changes.
- **Three ways to use it**: CLI, web console, and an MCP server (lets Claude and other AI
  assistants produce files directly, with no API key).

## Installation

Python 3.11+ is required. [LibreOffice](https://www.libreoffice.org/) is recommended: the third
gate, previews and the vision review all depend on it. Everything else works without it.

```bash
git clone https://github.com/FantasySakura0515/ODForge.git
cd ODForge/odforge
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\Activate.ps1
pip install -e ".[cjk,web]"
```

Optional extras:

| extra | Purpose |
| --- | --- |
| `cjk` | Word-aware CJK line breaking (jieba). Without it, lines may break between any two characters |
| `web` | The web console behind `odforge serve` |
| `vision` | Claude as the vision review backend |

## Choosing an LLM backend

Pass `--backend`, or set `ODFORGE_BACKEND` (default `codex`).

| Backend | Setup | Notes |
| --- | --- | --- |
| `codex` | [Codex CLI](https://github.com/openai/codex) 0.147.0+ installed and `codex login` done | Uses your own ChatGPT login, no API key; local use only. Set the model with `ODFORGE_CODEX_MODEL` |
| `ollama` | [Ollama](https://ollama.com/) running locally, default model `qwen2.5` | Fully offline |
| `custom` | `ODFORGE_CUSTOM_BASE_URL`, `ODFORGE_CUSTOM_MODEL` (`ODFORGE_CUSTOM_API_KEY` optional) | Any service that speaks the OpenAI API: DeepSeek, OpenAI, OpenRouter, vLLM and so on |

For example, DeepSeek:

```bash
export ODFORGE_BACKEND=custom
export ODFORGE_CUSTOM_BASE_URL=https://api.deepseek.com
export ODFORGE_CUSTOM_API_KEY=sk-...
export ODFORGE_CUSTOM_MODEL=deepseek-chat
```

Every backend can use separate models for the outline and slide stages. See
[`odforge/.env.example`](odforge/.env.example) for the full list of variables, including
image generation, vision review and the remote-image allowlist.

## Usage

### Generating documents

The file extension decides the document type.

```bash
# Presentation
odforge new "A 12-slide lesson on photosynthesis" -o photo.odp --language en

# Text document
odforge new "A lab report template: aim, method, results, discussion" -o report.odt --language en

# Spreadsheet (formulas are calculated when LibreOffice opens the file)
odforge new "Class grade sheet, final = midterm 30% + final exam 40% + coursework 30%" -o grades.ods --language en
```

Common presentation options:

| Option | Description |
| --- | --- |
| `--theme` | Color theme: `academic` `minimal` `dark` `teal` `forest` `navy` `violet` `crimson` `slate` `gold` `sky` `plum` `clay`; picked by the model if omitted |
| `--style` | Composition style, see below; defaults to the theme's paired style |
| `--mode` | `presenter` (less text) or `detailed` (meant to be read on its own) |
| `--language` | `zh-TW` (default), `en`, `bilingual` |
| `--interactive` | Print the outline and wait for confirmation before generating slides |
| `--from-template FILE` | Reuse the colors and fonts of an existing ODF template |
| `--image FILE` | Provide an image asset; repeatable |
| `--byline`, `--logo FILE` | Cover byline and logo; `--logo-placement` controls which slides show the logo |
| `--qa` | Run the vision review loop after rendering; needs LibreOffice and a vision backend |
| `--one-shot` | Generate the whole deck in a single call, for weaker local models |

The style decides the composition; the theme only decides colors and fonts:

| Style | Based on | Look |
| --- | --- | --- |
| `classic` | ODForge's original layout | Centered cover, accent bar beside titles, full-bleed section slides |
| `report` | Consulting-firm deck structure | Action titles top-left, hairline rule, source and page number in the footer |
| `academic` | Beamer metropolis theme | Rule under the title, progress bar at the bottom |
| `keynote` | Stage presentations | Full-bleed accent cover, large type only |
| `editorial` | Swiss graphic design | Full-width top rule, oversized faint numbers on section slides |
| `passport` | Reviews, proposals, progress reports | White framed cards, dark key-point panel on the right; the densest layout |
| `zen` | Minimal layouts | No rules, no footer |

For example, reuse your organization's template, add a logo, and let a vision model review
the result:

```bash
export ODFORGE_VISION_BACKEND=claude ANTHROPIC_API_KEY=...
odforge new "Quarterly project update" -o update.odp --language en \
  --from-template company.otp --logo logo.png --byline "Jane Doe · Platform Team" --qa
```

Vision backends: `claude`, `ollama`, `codex`, `custom`, selected with `ODFORGE_VISION_BACKEND`.

### Checking existing files

```bash
odforge check some.odp               # gates, style references and overflow; prints a Markdown report
odforge check some.docx -o diff.md   # convert .docx to .odt, compare the structure and check overflow
```

The overflow check has LibreOffice lay the file out, then compares where each line of text
actually landed:

- Presentations: text outside the frame it belongs to (naming any text it runs into) or off the slide.
- Text documents: text past the right margin, or running off the page and getting cut off
  (typically a table that is too wide).

Output looks like this:

```text
## 跑版
- 發現 2 處跑版:
  - 第 15 頁「17輸出順序」文字超出框的下緣 1.96 cm
  - 第 15 頁「前序 (Pre)」文字超出框的下緣 1.01 cm
```

`odforge new` runs it on every file it produces. Overflow is reported, not fatal: it does not
change the exit code. Without LibreOffice the check says it was skipped and is never shown as passed.

### Comparing models

```bash
odforge benchmark "High-school chemistry: acid-base neutralization" --backend codex --backend ollama --pages 10
```

Runs the same prompt on several backends, keeps each candidate's outline, IR, output file and
previews, and writes a structural comparison report.

## Web editor

```bash
odforge edit deck.odp            # needs the web extra and a built frontend (see the web console section)
```

Opens any `.odp`, not only ODForge's. Slides are drawn as real page elements, so what you see
is what you edit:

- Drag to move; edges snap to other objects and the page centre, with distances to the nearest
  neighbours shown. Hold ⌥ to move freely.
- Dragging a card carries the text inside it. Eight handles resize; Shift keeps the ratio.
- Double-click to retype. Enter starts a paragraph, Shift+Enter breaks a line; fonts, sizes and
  bullets are kept.
- Arrow keys nudge 0.5 mm (5 mm with Shift); marquee-select; ⌘D duplicates, Delete deletes,
  ⌘Z / ⇧⌘Z undo and redo.
- The slide list reorders by drag and duplicates, deletes or adds slides; the toolbar adds text
  boxes and rectangles.

Every step is written straight back to the file. Anything the editor does not touch (speaker
notes, pictures, objects it cannot draw) is left exactly as it was. When another program saves the
file (an AI assistant using `edit_odp` over MCP, say), the open editor updates within a second, so
you and the assistant can work on the same deck at once.

## Live preview: your agent writes, the browser shows

Hand the content to the AI agent you already use (Claude Code, Codex…). ODForge only lays it
out and checks it, so no LLM backend needs to be configured.

```bash
odforge preview deck.json        # needs the web extra and a built frontend (see below)
```

`deck.json` is a presentation IR. The command opens the browser; every time the agent saves
the file, the page re-lays it out within seconds, refreshes the thumbnails, marks slides that
overflow, and writes the `.odp` next to the JSON. Each version also prints a one-line summary
in the terminal (version, page count, overflow), so an agent running it in the background knows
what to fix.

[`odforge/skills/odforge-design`](odforge/skills/odforge-design/SKILL.md) describes this workflow;
give it to your agent.

## Web console

Build the frontend once before first use (from the `odforge/` directory; `odforge serve` then
serves it):

```bash
npm --prefix web ci
npm --prefix web run build
odforge serve        # http://127.0.0.1:8000
```

The flow:

1. **Describe what you need**, optionally attaching reference files (text is extracted from
   PDFs for the model to read; PNG/JPEG files become images the deck can use). Page count,
   occasion, audience, tone, language and theme can all be left for the model to decide.
2. **Interview**: the model asks about whatever is missing, usually 3–5 questions, and turns
   the answers into an editable brief. Generation starts only after you confirm it.
3. **Review the outline**: edit any slide's skeleton directly.
4. **Generate**: watch each slide come in with its preview and the results of all four gates;
   regenerate any single slide you don't like.
5. **Download**.

The template library lets you define your own style × theme combinations (insufficient
contrast is rejected on the spot) or import an organization's template directly. History and
templates are stored locally (in the user's application-data directory by default; change it
with `ODFORGE_SESSIONS_DIR`), so they survive reloads and browser changes.

The server has no authentication and binds to `127.0.0.1` by default. Binding to other
addresses requires `--allow-remote`, and the `codex` backend refuses to run when the server is
bound beyond loopback. `serve` loads `odforge/.env` automatically.

## Connecting AI assistants

```bash
odforge setup          # registers with Claude Code and Codex; odforge setup --remove undoes it
```

Registers the MCP server with Claude Code and Codex (user scope, so every project sees it), links
the `odforge-design` skill into both agents' skill folders, and links `odforge` into `~/.local/bin`
when no shell can find it. Then start a new conversation and ask for a deck.

In the editor, use the comment tool (C) to pin notes where something should change, then tell the
assistant to apply the comments: it makes each change, deletes the comments it resolved, and the
open editor follows within a second. Comments live inside the `.odp` (ODF's presentation
annotation format), so they travel with the file.

## MCP server

ODForge is also an MCP server. In this mode the AI assistant writes the Document IR itself and
ODForge only renders and validates it, so no API key is needed.

```json
{
  "mcpServers": {
    "odforge": {
      "command": "/path/to/ODForge/odforge/.venv/bin/odforge-mcp"
    }
  }
}
```

Seven tools:

| Tool | Purpose |
| --- | --- |
| `forge_presentation` | IR → `.odp` |
| `forge_text_document` | IR → `.odt` |
| `forge_spreadsheet` | IR → `.ods` |
| `inspect_odf` | Validate an existing ODF file and check it for overflow |
| `preview_odf` | Render each page to PNG so the assistant can check its work |
| `outline_odp` | List every element of an existing `.odp`: id, position, text |
| `edit_odp` | Edit an existing `.odp` in place — retype, move, add or remove slides — leaving the rest alone |

When text does not fit, `forge_*` still writes the file, but the returned string carries
`warning:` blocks: the overruns estimated from the layout budget before rendering, and the
places where LibreOffice actually laid text outside its frame or page, so the assistant can
shorten the text and render again.

[`odforge/skills/odforge-design`](odforge/skills/odforge-design/SKILL.md) is a skill for Claude
Code and similar agents. It teaches them how to write a good presentation IR and how to
check their work with `preview_odf`.

The server writes files to whatever path the client asks for. Only use it with assistants you trust.

## How it works

```text
A sentence
  │
  ▼
LLM ──► Document IR (JSON validated by pydantic; broken JSON is repaired or rejected)
  │
  ▼
Renderer ──► odfdo for .odt / .ods, hand-written XML for .odp
  │
  ▼
Gates ──► the file is delivered only if they pass
```

| Gate | Checks | On failure |
| --- | --- | --- |
| 1. Structure | zip layout, `mimetype` position, manifest | Not delivered |
| 2. XML | Every part is well-formed | Not delivered |
| 3. Conversion | LibreOffice converts it to PDF headlessly; spreadsheets are checked sheet by sheet for formula errors | Reported, still delivered |
| 4. Design | A vision model reviews each slide, repairs problems and re-renders | Reported, still delivered |

Gates 3 and 4 always report what actually happened: `pass`, `fail`, not enabled, or
undetermined. A check that did not run is never shown as passed. See
[`odforge/docs/gates.md`](odforge/docs/gates.md) for the full definitions.

The gates guarantee that the file is well-formed, opens, and has had its layout reviewed by a
model. **They do not verify the content.** Numbers, dates, quotes and sources may be made up by
the model; check them yourself.

## Development

```bash
cd odforge
pip install -e ".[dev]"

pytest -q
ruff check .

npm --prefix web ci
npm --prefix web test
npm --prefix web run typecheck
npm --prefix web run dev     # frontend dev server; /api is proxied to odforge serve (:8000)
npm --prefix web run build
```

CI runs two lanes: an unpinned one (Ubuntu and Windows) that catches upstream dependency
changes early, and one pinned with `constraints.txt` for reproducibility.

## Known limitations

- The table of contents in a new `.odt` is empty until you right-click it in LibreOffice and choose "Update Index".
- `.ods` has no native charts yet.
- Images can only be placed in presentations.
- `--from-template` extracts colors and fonts only; it does not reuse the template's master page layouts.
