## Why ODForge?

Nearly every AI-era document tool outputs PPTX/DOCX; leading open-source text-to-slides tools don't even offer ODP export. ODF (OpenDocument Format) is an international standard (ISO/IEC 26300) and the mandated document format for many governments — yet it has been left out of the AI wave.

Existing LibreOffice AI extensions (localwriter, LibreThinker, …) stop at "rewrite the selected text". No tool generates a **complete, structured, native ODF document from one natural-language sentence**. ODForge fills that gap.

## Core idea: AI generates the content — the engine guarantees the format

Asking an LLM to emit a file directly is rolling dice every time; ODForge replaces the dice with machinery.

```
One sentence from the user
     │
┌────▼─────────┐  The LLM only produces a "Document IR" —
│  LLM layer    │  structured JSON strictly validated by pydantic.
│ (pluggable)   │  The LLM never touches XML.
└────┬─────────┘  (Built-in json-repair: malformed model JSON is fixed or rejected)
     │ Document IR
┌────▼─────────┐  A deterministic rendering engine writes
│  Renderers    │  spec-compliant OpenDocument XML:
│               │  .odt/.ods via odfdo; .odp via hand-written XML
└────┬─────────┘  (theme system, five layouts, speaker notes, full CJK support)
     │ native ODF file
┌────▼─────────┐  1. zip structure (mimetype first & stored, manifest complete)
│  Three gates  │  2. XML well-formedness (every part)
│               │  3. Real LibreOffice conversion (headless → PDF must succeed)
└────┬─────────┘
     ▼
  Delivered via CLI, or reported back via MCP
```

Every output must pass all three validation gates before it reaches you — **the file you get is guaranteed to open**.

## Quick start

Requirements: Python 3.10+, [LibreOffice](https://www.libreoffice.org/) (used by the third gate; everything else works without it).

```powershell
git clone https://github.com/FantasySakura0515/ODForge.git
cd ODForge/odforge
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e .
```

Pick an LLM backend:

```powershell
# Option 1: DeepSeek (cloud)
$env:DEEPSEEK_API_KEY = "your-key"

# Option 2: Ollama (local, fully offline, nothing leaves your machine) — no key needed
# Install & start https://ollama.com/ then add --backend ollama
```

Generate documents:

```powershell
# Presentation (three themes: academic / minimal / dark)
odforge new "A 12-slide teaching deck on photosynthesis" -o photo.odp --theme academic

# Text document (TOC, heading hierarchy, tables)
odforge new "A lab-report template: purpose, method, results, discussion" -o report.odt

# Spreadsheet (with formulas — LibreOffice evaluates them on open)
odforge new "Class grade sheet, final = midterm 30% + final 40% + coursework 30%" -o grades.ods
```

Inspect existing files:

```powershell
odforge check some.odt              # three gates + style-reference integrity, Markdown report
odforge check some.docx -o diff.md  # docx → odt conversion structural diff (layout-drift detection)
```

## MCP: let any AI assistant produce ODF

ODForge doubles as an **MCP server**, exposing its deterministic rendering engine to AI assistants (Claude Desktop, or any MCP client). In this mode the assistant authors the Document IR itself and ODForge only renders and validates — **no API key required**.

```json
{
  "mcpServers": {
    "odforge": {
      "command": "<path-to-repo>/odforge/.venv/Scripts/python.exe",
      "args": ["-m", "odforge.mcp_server"]
    }
  }
}
```

Once registered, tell your assistant "make me a deck and save it to my desktop" — a validated `.odp` appears.

> **Trust model**: the server writes files to whatever path the MCP client requests. Use it only with assistants you trust (it is a local stdio tool).

## Field notes: ODF ecosystem issues we hit while building this

First-hand observations from development, shared for the community:

| Finding | Detail |
|---------|--------|
| CJK font-size trap | ODF CJK text needs separate `style:font-size-asian` / `style:font-weight-asian`; with only `fo:font-size`, CJK glyphs fall back to the default size — most tools miss this |
| odfpy is stale | The best-known Python ODF library has had no release since 2020 and only supports ODF 1.2 |
| odfdo's presentation gap | Actively maintained, but `.odp` master-page/layout support is thin (acknowledged upstream) — which is why our presentation renderer writes XML by hand |
| AI tools skip ODP | Mainstream open-source text-to-slides tools (e.g. Presenton) export only PPTX/PDF; ODF feature requests sit open |
| LLM structured output can't be trusted | DeepSeek function calling can emit unquoted string values (triggered by CJK-bracket-initial text); a repair layer plus schema validation is mandatory |

## Project layout

```
odforge/src/odforge/
├── ir.py           # Document IR: pydantic models (the system-wide contract)
├── llm.py          # Pluggable LLM backends (DeepSeek / Ollama / any OpenAI-compatible endpoint)
├── render/
│   ├── odt.py      # Text documents (odfdo)
│   ├── odp.py      # Presentations (hand-written XML, data-driven layouts)
│   └── ods.py      # Spreadsheets (numeric cells + native formulas)
├── themes.py       # Themes & layout geometry (pure data)
├── package.py      # ODF zip packaging (mimetype rule + manifest)
├── validate.py     # The three validation gates
├── check.py        # Inspection reports + docx↔odt structural diff
├── cli.py          # odforge new / check
└── mcp_server.py   # MCP tools (take IR, not prompts; no key needed)
```
